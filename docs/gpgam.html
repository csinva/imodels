GPGam: Additive Gaussian Processes over Binned Features

🗂️ API, 🔗 Github

GPGam fits a generalized additive model with pairwise interactions (a GA2M). Every shape function in it is a Gaussian process over the quantile bins of its feature.

One quantity settles every choice the model makes: the exact GP marginal likelihood. It sets how smooth each curve should be, which features matter, which interactions to include, and how finely to grid them. Nothing is chosen by cross-validation, there is no validation split, no bagging and no seed, so two fits on the same data give the same model.

Why binning makes an exact GP cheap

Fitting a GAM as a Gaussian process normally means an n×n kernel matrix, which is hopeless past a few thousand rows. Every component of a GA2M is a function of one feature, or of two on a grid. So once the features are binned, each component is just a function on a small grid, holding one value per bin.

Write Z for the indicator matrix recording which bin each row falls in. Then the exact marginal likelihood touches the data only through three quantities:

C = Z.T @ Z      # bin co-occurrence counts
b = Z.T @ y      # bin sums
y.T @ y

That is P×P numbers plus P more, where P is the total number of bins. A budget holds P to a few thousand. One pass over the data computes all of it, and every optimizer step after that uses those numbers alone. So each step costs O(P³) no matter how many rows there are. A hundred thousand rows cost what a thousand rows cost.

What the likelihood decides

Each feature gets a prior built from two covariance kernels on its bin grid. A Matérn ½ kernel at a short lengthscale produces rough shapes that can turn sharply. A squared exponential kernel at a longer lengthscale produces smooth shapes. Their amplitudes are free parameters, so maximizing the likelihood picks the blend for each feature separately. Smoothness is inferred, not tuned. A feature that needs a step and a feature that needs a gentle curve are both handled, and neither requires a search over lengthscales.

Those same amplitudes also select features. A feature that explains nothing has its amplitude driven toward zero and drops out of the model. This is automatic relevance determination, and it comes free from the same objective. Interactions are screened on the residual and then fit in blocks that share shrinkage, and the grid resolution for each block is chosen by comparing marginal likelihoods.

An example using GPGam

from imodels import GPGamRegressor
from sklearn.datasets import make_friedman1
from sklearn.model_selection import train_test_split

X, y = make_friedman1(n_samples=800, noise=1.0, random_state=0)
X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=0)

model = GPGamRegressor().fit(X_train, y_train)
preds = model.predict(X_test)

The fitted model is a set of lookup tables, so you can read it directly instead of explaining it after the fact:

grid, values = model.shape_function(0)   # feature 0's fitted curve
model.interaction_terms()                # the pairs the model chose
# [(0, 1), (6, 7), (4, 6), (3, 8)]

On this data the first interaction GPGam selects is (0, 1). That is the interaction Friedman’s function contains, since its first term is 10 sin(π x₀ x₁).

Reading a fitted model

Below is a GPGam fit to the California housing data, 16,512 training rows and eight features, predicting median house value in hundreds of thousands of dollars. It reaches an R2 of 0.8383 on a held-out fifth of the data. Nothing about the fit was tuned.

Because the model is a sum of one curve per feature, the fit is the explanation. Each curve below shows what the model adds to its prediction at each value of that feature, and the shaded band is the Gaussian process posterior, two standard deviations wide. Click a feature to look at it closely.

Two things are worth noticing in that panel. The curves are ordered by how much they move, and the bottom two barely move at all: Population and AveBedrms span less than $12k across their entire range. No selection step removed them. Their kernel amplitudes were driven near zero by the same likelihood that fit everything else, which is what automatic relevance determination does.

The bands widen toward the ends of every curve. That is not a density effect: quantile bins hold roughly equal counts by construction, and for MedInc the end bins hold 64 points against 63 in the middle. It is an edge effect. A bin in the middle of the grid borrows strength from neighbours on both sides, while a bin at the end has neighbours on one side only, so the prior pins it down less firmly. HouseAge shows the widest bands because both causes apply at once: its end bins genuinely do hold fewer houses.

The strongest single effect is not income but geography. Longitude and Latitude span $426k and $388k, against $253k for MedInc. They should be read together rather than separately, and the model says so itself: the first interaction it selected was exactly the pair (Latitude, Longitude).

How well does it do?

Four regression benchmark suites were used, covering 113 datasets that range from 50 to 72,000 rows and up to 1,024 features. GPGam is the strongest interpretable model on three of them, and ties explainable boosting machines on the fourth.

SuiteGPGamEBMNotes
imodels (65 datasets)4.605.00 mean rank, capped at 1k training rows
Classic-7 (full size)2.433.43 wins 6 of 7 against EBM
TabArena-132.692.69 tied with EBM; wins 6 of 13
OpenML-CTR23 (28)2.112.32 held out; pool of interpretable models

CTR23 is the most informative of the four. It was downloaded after the method was finished and was used for no design decision, so it measures whether the model generalizes rather than whether it was tuned. Only TabPFN ranks higher overall, and TabPFN is a black box that cannot fit several of the wider datasets at all.

The model fails in the same way on every suite, which is worth knowing before you use it. It loses on smooth simulations and on data with strong interactions, such as wave energy converters, building energy simulation, and robot arm dynamics. In all of those the target depends on three or more inputs at once, and no sum of pairwise pieces can represent that. This is a limit of the model class, not of the fitting procedure.
