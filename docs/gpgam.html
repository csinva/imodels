GPGam: Additive Gaussian Processes over Binned Features

🗂️ API, 🔗 Github

GPGam fits a generalized additive model with pairwise interactions (a GA2M) in which every shape function is a Gaussian process over the quantile bins of its feature. Every structural choice the model makes — how smooth each curve should be, which features matter, which interactions to include and how finely to grid them — is made by maximizing one quantity, the exact GP marginal likelihood. There is no cross-validation, no train/validation split, no bagging and no seed, so two fits on the same data give the same model.

Why binning makes an exact GP cheap

Fitting a GAM as a Gaussian process normally means an n×n kernel matrix, which is hopeless past a few thousand rows. But every component of a GA2M is one-dimensional (or a two-dimensional grid), so once each feature is quantile-binned, each component is just a function on a small grid — one value per bin.

Write Z for the indicator matrix recording which bin each row falls in. Then the exact marginal likelihood touches the data only through three quantities:

C = Z.T @ Z      # bin co-occurrence counts
b = Z.T @ y      # bin sums
y.T @ y

Those are P×P and P numbers, where P is the total number of bins — a few thousand, fixed by a budget. A single pass over the data builds them, and every optimizer step afterwards works on them alone. The fit therefore costs O(P³) per step regardless of the sample size: a hundred thousand rows cost the same as a thousand.

What the likelihood decides

Each feature's prior is built from exactly two covariance kernels on its bin grid: a Matérn-½ at a short lengthscale, which produces rough, locally adaptive shapes, and a squared-exponential at a longer one, which produces smooth shapes. Their amplitudes are free parameters, so maximizing the likelihood chooses the blend per feature. Smoothness is inferred rather than tuned, and a feature needing a step and a feature needing a gentle curve are both served without a lengthscale search.

The same amplitudes perform feature selection. A feature that explains nothing has its amplitude driven toward zero and drops out — automatic relevance determination, obtained for free from the same objective. Interactions are screened on the residual, then fit in blocks that share shrinkage, with each block's grid resolution chosen by comparing marginal likelihoods.

An example using GPGam

from imodels import GPGamRegressor
from sklearn.datasets import make_friedman1
from sklearn.model_selection import train_test_split

X, y = make_friedman1(n_samples=800, noise=1.0, random_state=0)
X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=0)

model = GPGamRegressor().fit(X_train, y_train)
preds = model.predict(X_test)

The fitted model is a set of lookup tables, so it can be read directly rather than explained after the fact:

grid, values = model.shape_function(0)   # feature 0's fitted curve
model.interaction_terms()                # the pairs the model chose
# [(0, 1), (6, 7), (4, 6), (3, 8)]

On this data the first interaction GPGam selects is (0, 1) — which is the interaction Friedman’s function actually contains, since its first term is 10 sin(π x₀ x₁).

How well does it do?

Across four regression benchmark suites — 113 datasets in total, ranging from 50 to 72,000 rows and up to 1,024 features — GPGam is the strongest interpretable model on three suites and ties explainable boosting machines on the fourth.

SuiteGPGamEBMNotes
imodels (65 datasets)4.605.00 mean rank, capped at 1k training rows
Classic-7 (full size)2.433.43 wins 6 of 7 head-to-head
TabArena-132.692.69 tied with EBM; wins 6 of 13
OpenML-CTR23 (28)2.112.32 held out; interpretable-model pool

CTR23 matters most of the four: it was downloaded after the method was finished and was used for no design decision, so it measures whether the model generalizes rather than whether it was tuned. Only TabPFN, a black-box foundation model, ranks higher overall, and it cannot fit several of the wider datasets at all.

The model’s failure mode is consistent and worth knowing: it loses on smooth deterministic simulations and heavy-interaction data — wave-energy converters, building-energy simulation, robot arm dynamics — where the target depends on three or more inputs jointly. No sum of pairwise pieces can represent that, and this is a limit of the model class rather than of the fitting procedure.
