AutoOptTree: certifiably optimal decision trees via Autoresearch

Chandan Singh · September 2026

📄 Paper, 🗂 Doc, 📌 Citation

Decision trees are fit greedily in practice: CART and C4.5 pick each split without regard to the splits below it, so the tree they return can be far from the best tree of its size, and there is no way to tell from the output how far. Finding the actual optimum is NP-hard, and the exact solvers that do it (GOSDT, STreeD) spend most of their budget proving optimality rather than finding the tree, which is why they are rarely used. Here we introduce AutoOptTree, an exact solver discovered through autoresearch with frontier agents. It certifies optimality on 63 of 70 benchmark problems against 46 for GOSDT, and where both finish it is 59× faster on geometric mean. The speedup comes entirely from stronger admissible bounds, so every tree it returns is still a proven optimum.

1. Quickstart & example usage

from imodels import AutoOptTreeClassifier
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split

X, y = load_breast_cancer(return_X_y=True, as_frame=True)
X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=42)

model = AutoOptTreeClassifier(regularization=0.05).fit(X_train, y_train)
preds = model.predict(X_test)

There is no max_depth. regularization sets what a leaf costs, in units of misclassification rate, and the model returns the best tree at that price, however deep that turns out to be. A leaf that does not improve the training error by regularization is never worth adding, so the trees stay small on their own.

The fitted model reports whether the search finished, and what it proved:

model.optimal_      # True: no other tree on these features scores better
model.objective_    # 0.1775, the proven minimum of error + 0.05 * leaves
model.n_leaves_     # 2
print(model)        # the tree, as nested if/else on the caller's feature names

At this price a leaf is expensive, and the best tree that exists on breast cancer is a single threshold, which reaches 89.5% on the held-out quarter:

if mean concave points >= 0.05128 then:
    class = 0
else:
    class = 1

optimal_ is the part greedy trees cannot offer. When it is True, the objective reported is a minimum over every tree that exists on the binarized features, not the best of those that happened to be tried. When the time limit is hit first it is False, the model warns, and lowerbound_ and upperbound_ bracket how much could still be left on the table.

What makes a problem expensive is the number of distinct values in the data, not the number of rows: each one is a candidate split. Breast cancer's 30 continuous columns become 11,513 binary features, and the search above certifies in 0.15 seconds only because a leaf priced at 0.05 rules most trees out immediately. Drop regularization to 0.02 and the same problem does not finish in a minute. Discretizing the features first, or pricing leaves higher, is what keeps an exact solver exact in practice.

2. Experimental results

AutoOptTree was produced by the autoresearch loop described in Agentic-imodels (code on github). An agent was given a working exact solver, a fixed benchmark, and a gate that no change may ever return a tree that is not optimal; it proposed bounds, proved them admissible, measured them, and kept the ones that won.

The benchmark is 70 problems: 14 datasets crossed with five values of regularization (0.1, 0.05, 0.02, 0.01, 0.005), each given 30 seconds and 6 GB. Every returned tree's objective is recomputed independently from the tree and the raw data, and checked against the known optimum for that problem, so a solver cannot score by misreporting.

The one false certificate is GOSDT's, on tic-tac-toe at regularization=0.02: it reports a tree as optimal whose objective is worse than a tree AutoOptTree certifies. The cause is a scope-conditional lower bound cached unconditionally, confirmed by a two-line patch to the reference implementation. gosdt-guesses in guided mode is a heuristic by design, so it certifies nothing; it is listed to show what the search space costs.

Seven problems are certified by nobody, including AutoOptTree, within the cap: they are the widest continuous datasets, where a column contributes one candidate split per distinct value. No solver in the table certifies them within 600 seconds either.

Accuracy experiments against greedy trees on held-out data are in progress and will be added here: the open question is how much of the optimality gap survives to test time.

3. Methods: AutoOptTree

The objective is the one GOSDT introduced,

minimise   misclassification rate + regularization * (number of leaves)

over every decision tree on the binarized features. The search is a memoised depth-first branch-and-bound. The subset of training rows reaching a node (its capture set) is held as a single Python big integer, so a subproblem is one dictionary key and identical subproblems reached by different paths are solved once. Each subproblem carries an interval [lb, ub] on its optimal risk and a budget; the recursion either closes that interval or proves the optimum exceeds the budget, which is what makes the final answer a certificate rather than an incumbent.

Everything that made it faster is a bound, and every bound is admissible: they change which subproblems are visited, never which tree is optimal. The ones that did the most work:

  • Pairwise counts give exact two-leaf values. Counting every pair of candidate splits at a node yields, for each child, the exact loss of its best two-leaf tree. A node whose budget cannot afford four leaves is then solved outright, with no recursion at all.
  • A shape relaxation bounds everything larger. Any tree with four or more leaves has a root split whose two sides have some number of leaves each. Combining the exact one- and two-leaf values with a cheap floor for three-leaf subtrees bounds every such tree at once, so a node can be certified without expanding a single child.
  • Triples give exact depth-3 values. Counting triples of candidate splits yields each child's exact best three-leaf and best (2,2)-leaf tree. It costs O(m³) per node, so it is used only where the node is narrow enough to pay for itself.

The per-node counting runs in numba kernels over packed 64-bit words, and rows are ordered so that the capture sets of deep nodes occupy few of those words. Together the bounds and the kernels account for the 59×: the starting solver spent its time proving that subtrees it had already explored could not be beaten, and most of that proving is now done arithmetically from counts the node already has.

A fuller description of each bound, the ablations, and the ideas that were proved sound but measured to be worthless, is in progress.
